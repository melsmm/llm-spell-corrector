# LLM Spell Corrector — автоматическая коррекция ошибок в русскоязычных текстах

Проект по обучению большой языковой модели (LLM) для задачи **исправления орфографических, пунктуационных и регистровых ошибок** в русскоязычных текстах.

В качестве базовой модели взята [`RefalMachine/RuadaptQwen3-4B-Instruct`](https://huggingface.co/RefalMachine/RuadaptQwen3-4B-Instruct) — адаптированная под русский язык версия [`Qwen/Qwen3-4B-Instruct-2507`](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507). Модель дообучалась через **LoRA** в фреймворке [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory).

## 💡 Мотивация

Существующие SOTA-решения для русского spell correction (например, [SAGE](https://github.com/ai-forever/sage) на архитектуре T5) показывают высокие метрики, но имеют ряд недостатков:

- **сложный и дорогой инференс** — архитектура T5 хуже оптимизирована для продакшена;
- **сложность дообучения** под новые доменные области.

Цель проекта — получить модель, которая:

- ✅ работает **значительно быстрее** (инференс через [vLLM](https://github.com/vllm-project/vllm));
- ✅ **проще внедряется** в продакшен (OpenAI-совместимый API «из коробки»);
- ✅ легко **дообучается под новый домен** (например, медицину) с помощью LoRA;
- ✅ показывает **конкурентные** (пусть и не лучшие) метрики качества.

## 🗺️ Этапы проекта

1. **Сбор данных** — готовые датасеты для spell correction + чистые корпусы текстов из разных доменов.
2. **Синтетическая генерация ошибок** — с помощью [SAGE](https://github.com/ai-forever/sage) (`SBSC`, `CharAug`, `WordAug`) + собственный алгоритм внесения пунктуационных ошибок.
3. **Подготовка двух датасетов:**
   - `synth_spell_correction_1m` — **1 млн** синтетических примеров;
   - `spell_correction_30k` — **~30 тыс.** примеров из объединённых готовых пар.
4. **Сбор статистик** по датасетам (длины текстов, CER, распределения по источникам/методам).
5. **Двухстадийное LoRA-дообучение:**
   - **Stage 1** — обучение на 1 млн синтетических примеров → LoRA-адаптер;
   - **Stage 2** — продолжение обучения этого же адаптера на 30 тыс. качественных готовых пар (идея: дать модели увидеть более качественные примеры в конце обучения).
6. **Мерж** адаптера с базовой моделью.
7. **Инференс** через vLLM (OpenAI-совместимый сервер).
8. **Оценка** на бенчмарке [`ai-forever/spellcheck_punctuation_benchmark`](https://huggingface.co/datasets/ai-forever/spellcheck_punctuation_benchmark) и сравнение с SAGE, GPT-3.5, GPT-4.
9. **Замеры времени инференса** относительно SAGE.
10. **Демо** — VK-бот для интерактивной проверки работы модели.

## 🚀 Запуск модели

### Инференс через vLLM

Базовую модель можно поднять с подключаемым LoRA-адаптером:

```bash
vllm serve /path_to_base_model \
    --enable-lora \
    --lora-modules spell_correction=/path_to_adapter \
    --max-lora-rank 32 \
    --gpu-memory-utilization 0.95 \
    --host 0.0.0.0 \
    --port 9900 \
    --served-model-name RuadaptQwen3_4B_Instruct \
    --max-model-len 4096
```

Либо, поскольку адаптер уже смержен в [итоговую модель](https://huggingface.co/melsmm/Spell-Corrector-RU-4B), её можно запустить напрямую без `--enable-lora`.

### Формат запроса

Модель ожидает следующий промпт:

```
Исходный текст:
{текст с ошибками}

Отредактируй исходный текст, исправив ошибки.
```

Рекомендуемые параметры генерации: `temperature=0.1`, `top_p=0.7`.

Пример обращения через OpenAI-совместимый клиент:

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:9900/v1", api_key="EMPTY")

resp = client.chat.completions.create(
    model="spell_correction",
    messages=[{"role": "user", "content":
        "Исходный текст:\nпривет как дила\n\nОтредактируй исходный текст, исправив ошибки."}],
    temperature=0.1,
)
print(resp.choices[0].message.content)
```

### Выводы по метрикам

- **Stage 2 стабильно превосходит Stage 1** почти по всем метрикам — особенно заметен прирост по пунктуации и регистру, что подтверждает эффективность дообучения на качественных готовых парах в конце.
- По орфографии модель **уступает SAGE**, но по **пунктуации и регистру конкурентна**, а на некоторых доменах (RUSpellRU, GitHubTypoCorpusRu) — превосходит.
- Модель уверенно **обходит gpt-3.5-turbo и gpt-4** на большинстве срезов.
